# Data dictionary: source tables

All data is fictional and generated by `data_generator/generate_data.py` (seed 42).
Period: **2026-01-01 to 2026-06-30**. Business timestamps are local restaurant
time (America/Chicago) with no time zone. `customers.updated_at` is UTC.

"DQ" marks a deliberate data-quality issue that silver must handle (see the DQ log in `CLAUDE.md`).

---

## 1. `locations` (GitHub CSV: `data/github/locations.csv`, 20 rows)

| Column | Type | Null | Description |
|--------|------|------|-------------|
| location_id | int | no | PK. 1-20. #20 = Katy (opened 2026-04-01), #9 = Lakewood (problem location) |
| name | string | no | e.g. "Bayou Bites Montrose" |
| city | string | no | City. **DQ:** 3 rows with bad casing or whitespace (`houston`, ` Houston `, `SAN ANTONIO `) |
| region | string | no | Metro area: Houston (7), Dallas (5), Austin (4), San Antonio (4). Campaign targeting uses this |
| open_date | date | no | `YYYY-MM-DD` |
| seats | int | no | Dining room seats |
| has_drive_thru | boolean | no | `True`/`False`. Only these locations have `drive_thru` orders |
| manager_name | string | no | General manager |

## 2. `menu_items` (GitHub CSV: `data/github/menu_items.csv`, 35 rows)

| Column | Type | Null | Description |
|--------|------|------|-------------|
| item_id | int | no | PK. 1-35 |
| item_name | string | no | e.g. "Boudin Quesadilla" (#17) |
| category | string | no | `Entree` (17), `Side` (8), `Drink` (6), `Dessert` (4) |
| price | string → decimal(6,2) | no | Menu price in USD. **DQ:** 3 rows stored as `$12.99` |
| cost | decimal(6,2) | no | Food cost per unit (for margin) |
| is_spicy | boolean | no | |
| launched_date | date | no | Boudin Quesadilla = 2026-05-01; everything else earlier |

## 3. `orders` (GitHub CSV, one file per month: `data/github/orders/orders_2026_MM.csv`, 30,452 rows / 30,091 unique orders)

| Column | Type | Null | Description |
|--------|------|------|-------------|
| order_id | bigint | no | Business key (1000001+). **DQ:** 361 ids appear twice (re-exported in the next month's file; 107 re-exports carry an updated `order_status`) |
| location_id | int | no | FK → locations |
| customer_id | int | **yes** | FK → customers. Null = guest order (~35%) |
| order_ts | string → timestamp | no | Order time. Mostly `YYYY-MM-DD HH:MM:SS`. **DQ:** ~2% as `MM/DD/YYYY HH:MM` |
| channel | string | **yes** | `dine_in`, `takeout`, `delivery`, `drive_thru`. **DQ:** ~1.5% null |
| promo_code | string | yes | Campaign promo code redeemed (FK → campaigns.promo_code), null if none |
| payment_type | string | no | `credit_card`, `debit_card`, `apple_pay`, `cash`, `gift_card` (no cash on delivery) |
| order_status | string | no | `completed` (~95%), `cancelled`, `refunded`. **Business rule:** revenue counts completed orders only |

File placement: an order normally lands in the file for its month. **DQ:** 60 orders from 2026-01-28 to 2026-01-31 arrive only in the February file (late-arriving data).

## 4. `order_items` (GitHub CSV, one file per month: `data/github/order_items/order_items_2026_MM.csv`, 73,724 rows)

| Column | Type | Null | Description |
|--------|------|------|-------------|
| order_item_id | bigint | no | PK (5000001+) |
| order_id | bigint | no | FK → orders. **DQ:** 439 orphan rows whose order_id does not exist |
| item_id | int | no | FK → menu_items |
| quantity | int | no | Units. **DQ:** 740 rows with 0 or negative quantity |
| unit_price | decimal(6,2) | no | Price charged per unit (clean numeric) |
| discount_amount | decimal(6,2) | no | Promo discount on the line (0.00 if none) |

Line revenue = `quantity * unit_price - discount_amount`.
An order's items are in the file where the order *first* appears.
